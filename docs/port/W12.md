### 2. Befund: Forges `nextInt`-Schutz fehlt im geteilten Decorator

Die Forge-1.7.10-Patchdatei `patches/minecraft/net/minecraft/world/biome/BiomeDecorator.java.patch` (Zweig `1.7.10`
im MinecraftForge-Repository, gelesen am 2026-09-14) ersetzt in `genDecorations` jedes
`randomGenerator.nextInt(getHeightValue(x, z) * 2)` (und das `+ 32` der Blumen) durch einen privaten Helfer:

```java
private int nextInt(int i) {
    if (i <= 1)
        return 0;
    return this.randomGenerator.nextInt(i);
}
```

`world/gen/BiomeDecorator` wurde aus dem Vanilla-Jar (`aia`, `client-1.7.10.jar`) portiert, der den Patch nicht
enthält, und ruft `rand.nextInt(h * 2)` direkt. Bei einer leeren Spalte ist `h = 0`, und
`Random.nextInt(0)` wirft `IllegalArgumentException` – die Chunk-Generierung bricht ab. In Utopia, Mining und
VillageMania gibt es keine leeren Spalten; **in Chaos (schwebende Steinlagen über dem Void) schon.** Seit Chaos den
ganzen Decorator ruft, ist das ein Absturzkandidat. Der Helfer muss in `world/gen/BiomeDecorator` (nicht in diesem
Auftrag, steht als Eintrag für den Integrator) – er ist 1:1 zum Original, nicht R18-Fall 1: 1.7.10 lief mit Forge.
Für `h > 0` ändert er keine Zahl, also auch nichts in den drei anderen Dimensionen.

**Befund beim Schreiben, kein Portfehler:** Magic-Apple-Bäume (`(float) inx + 0.5f`) und `WorldGenMinable`
(`(float) (x + 8) + sin * n / 8`) rechnen in `float` auf Blockkoordinaten. Die Form hängt deshalb von der Größenordnung
der Koordinate ab (ab 2^24 Blockabstand 1, bei 2^20 schon 1/8) – 1:1 wie 1.7.10. Nähte entstehen dadurch nicht, weil
jeder Chunklauf dieselben Koordinaten rechnet; ein Vergleich zweier Bauten an verschiedenen Orten stimmt aber nur,
wenn beide im selben Zweierpotenz-Intervall liegen und um Vielfache von 16 verschoben sind. Die Tests legen alles in
[2^20, 2^21).
