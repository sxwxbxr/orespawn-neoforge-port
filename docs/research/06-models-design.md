# OreSpawn 1.7.10-20.3 - models and design, port notes for NeoForge 1.21.1

Stand: 10.09.2026. Ziel laut Vorgabe: NeoForge 1.21.1, private Nutzung, Originalmodelle/-texturen/-sounds 1:1 wiederverwendbar. Tabellen und Bezeichner englisch.

## Summary

- **109 of 109** `ModelBase` subclasses parsed from constructor bytecode, **0 failed**; 3584 parts, 3584 boxes (exactly one box per part), geometry JSON per model in `jar/models/<Model>.json`.
- Validation: `javap -c` spot checks on 3 models; full comparison against the decompiled constructors: 3584 of 3584 parts identical (texture offset, box, pivot, rotation, texture size).
- No model uses `addChild` (flat part list), `addBox(..., inflate)`, named boxes, `offsetX/Y/Z` or an effective `mirror`. Every `part.mirror = true` is written **after** `addBox`, which in 1.7.10 has no effect on the already baked box.
- 754 parts call `setTextureSize(w, h)` with values different from the model's `textureWidth/Height` - also after `addBox`, so without effect. The UVs of every box were baked with the model's declared texture size (0 exceptions).
- 885 boxes have fractional origins; box sizes are integers.

## Mapping recipe (1.21.1)

For each part in `models/<Model>.json` (one box per part, `name` = Java field name):

```java
root.addOrReplaceChild("<name>",
    CubeListBuilder.create().texOffs(uv[0], uv[1]).addBox(ox, oy, oz, w, h, d),
    PartPose.offsetAndRotation(px, py, pz, rx, ry, rz));
...
return LayerDefinition.create(mesh, textureWidth, textureHeight);
```

`uv`, `origin`, `size` from `boxes[0]`, `pivot` and `rotation_rad` from the part. This is mechanical and can be generated from the JSON. The OreSpawn `render()` body splits into `setupAnim` (all writes to `rotateAngle*` / `rotationPoint*`) and `renderToBuffer` (the `part.render(f5)` calls, plus the GL passes listed below).

### Renderer-side scaling and passes

- 130 of the 141 renderer registrations call `glScalef` (details in `jar/renderers_dump.txt`); the usual form is `glScalef(this.scale, this.scale, this.scale)` in `preRenderScale`, called from `preRenderCallback` -> in 1.21.1 override `LivingEntityRenderer.scale()`. In RenderGodzilla the `scale` field is set from the third constructor parameter (the second float of the registration); the other constructors were not checked one by one. RenderGodzilla, RenderTheKing and RenderKraken use `scale / 4`, `/ 4` and `/ 3` when `getPlayNicely() != 0` (condition read in the decompiled source); RenderTheQueen has the same `/ 4` branch in bytecode. 19 renderers have a `scale / 2` branch whose condition was not extracted: RenderBaryonyx, RenderBeaver, RenderCamarasaurus, RenderCassowary, RenderCaterKiller, RenderChipmunk, RenderEasterBunny, RenderFlounder, RenderGammaMetroid, RenderGazelle, RenderHydrolisc, RenderLizard, RenderOstrich, RenderPeacock, RenderRubberDucky, RenderStinkBug, RenderVelocityRaptor, RenderWaterDragon, RenderWhale. - The first float is passed to `RenderLiving` as shadow size; RenderGodzilla passes `arg1 * arg2` (`RenderLiving.<init>(model, L2 * L3)`), other renderers were not checked individually.

- Item renderers (`IItemRenderer`, item field "lang name" -> model (texture)): `MyBertha` "Big Bertha" -> `ModelBertha` (`Berthatexture.png`); `MySlice` "Slice" -> `ModelSlice` (`Slicetexture.png`); `MyRoyal` "Royal Guardian Sword" -> `ModelSlice` (`Royaltexture.png`); `MySquidZooka` "SquidZooka!" -> `ModelSquidZooka` (`SquidZookatexture.png`); `MyHammy` "Attitude Adjuster" -> `ModelHammy` (`AttitudeAdjustertexture.png`); `MyBattleAxe` "Battle Axe" -> `ModelBattleAxe` (`BattleAxetexture.png`); `MyChainsaw` "Chainsaw" -> `ModelChainsaw` (`Chainsawtexture.png`); `MyQueenBattleAxe` "Queen Scale Battle Axe" -> `ModelQueenBattleAxe` (`QueenBattleAxetexture.png`). 1.21.1: `BlockEntityWithoutLevelRenderer` via `IClientItemExtensions`, same `LayerDefinition`s; the 1.7.10 renderers apply per-render-type `glScalef`/`glRotatef`/`glTranslatef` (`renderSword`, `renderSwordF5`) that map to item display transforms.

### ModelPart or GeckoLib

- Every model is technically portable 1:1 to `ModelPart`/`LayerDefinition`: boxes only, flat, one texture size, no mirror/inflate. The effort is the animation code, not the geometry.
- GeckoLib is available for NeoForge 1.21.1 (4.9.2 on Modrinth, checked with `tools/check.py`). It is the sensible alternative where `render()` is thousands of bytes of hand-written kinematics and the part count exceeds ~100 (King, Queen, Prince Adult/Teen, Triffid, Kraken, Nightmare, TrooperBug, Leon): export the JSON geometry to Blockbench, re-animate there. Bedrock/GeckoLib geometry uses its own axis and pivot conventions - the conversion was not verified here and is a work item.
- Scale is not a reason for GeckoLib: the giant sizes come from `LivingEntityRenderer.scale()` plus plain box coordinates (largest box edge 80 model px in ModelGodzilla, pivots up to several hundred px in ModelKraken), which `ModelPart` handles as floats.
